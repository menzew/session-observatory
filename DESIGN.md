# Design

A developer reviews an unexpectedly expensive run on a laptop in a bright office, moving between a dense ledger and its evidence. Use white surfaces, dark readable ink, a subdued neutral sidebar, and a restrained deep rose accent (OKLCH hue 340) for selection and actions. The main work is a sortable, searchable ledger with an evidence drawer. Use a system sans, tabular numerals, 14px data, 30px page titles, thin dividers, and small radii. Show provenance and uncertainty adjacent to claims. All controls must work by keyboard; small screens scroll tables within their own region.


## Browser-first workflow

The first screen is **Sources & privacy**. A new user should understand what choosing a folder reads and how to try fictional data before importing personal evidence. Keep storage status and explicit Save accessible throughout analysis; avoid language that suggests autosave, live account monitoring, or automatic filesystem access.

Explain privacy at the relevant action: imports read selected files, backups contain private metadata, restore replaces the current tab, and Forget leaves original files and downloads intact. Use plain language in the interface and link supporting documentation where available. Do not require users to understand WebAssembly, SQLite, or HTTP to use the browser edition.

Use fictional data in examples and public screenshots. Show missing evidence and uncertainty next to totals and cost comparisons, and preserve an obvious path from every chart to its underlying records.
